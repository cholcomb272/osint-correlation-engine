# Contributing

Thank you for improving evidence-driven infrastructure intelligence.

1. Open an issue describing the evidence or engineering problem.
2. Keep changes incremental and preserve database compatibility.
3. Add deterministic fixtures and tests; core tests must not require live services.
4. Run backend tests, frontend tests/build, and dependency audits.
5. Document source provenance, timestamp semantics, and false-positive risks for collector/correlation changes.
6. Never add private feeds, active probing, secrets, real incident claims without sources, or synthetic data presented as telemetry.

Pull requests should state what changed, migration impact, test evidence, security considerations, and known limitations. By contributing, you agree that your work is licensed under Apache-2.0.
